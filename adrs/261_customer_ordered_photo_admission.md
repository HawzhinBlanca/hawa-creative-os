# ADR261 — Owned ordered customer photos

Date: 2026-10-02. Status: accepted for local implementation; not deployed.
Requirements: FR-006, FR-018, FR-068, NFR-006. Sources: docs/09_MESSAGING_AND_OFFICE_INBOX.md; docs/08_MEMORY_RAG_CLIENT_DNA.md; docs/14_SECURITY_THREAT_MODEL.md; MASTER_SPEC.md; ADR256/259/260.

Website uploads are immutable account/client receipts, not approved brand assets or Telegram events. Each raw JPEG/PNG/WebP is bounded to 10 MiB, sniffed, dimension limited (24 million pixels, 12,000 per axis) and actually decoded by the already installed ffmpeg with a forced image decoder, file/network protocols disabled, one thread, bounded allocation/output and an eight second deadline. At most two complete HTTP photo uploads (including body buffering) and two decodes run per Core process. Overload is rejected before reading bytes; stalled body deadlines release the slot. Originals remain unchanged and content addressed; no model, OCR or permanent taste promotion occurs on upload. Account admission is locked/rechecked, with 100 MiB / 40 upload receipts per rolling day before new storage. Same-key exact hash/filename/media retries return the same receipt without consuming another quota.

A brief names at most 20 distinct owned receipt IDs, in requester order. Admission rejects missing, foreign-account, foreign-client, duplicate-content and revoked receipts. Core reconstructs a hash-checked ordered manifest, rechecks it at lifecycle projection, and atomically binds originals as task files. Studio matches the complete task-file set and reads verified originals in this order. No synthetic Telegram ID or album is created. The web manifest is server authored and retained in the existing task source/outbox.

A separate explicit photo choice supports automatic content-aware selection, use-all, or a count. Automatic selection permits one or multiple photos and does not force a collage. Explicit choice enters the existing composition/coverage policy as a clearly attributed instruction; exact factual copy is untouched. Existing text instructions remain honored. Logo selection stays governed by Client DNA. Unsubmitted upload receipts are garbage-collection roots and are not globally downloadable by hash. Receipt retention/deletion needs a future governed policy, not silent expiry of retry evidence.

Acceptance: mounted authenticated streaming route bounds/deadline, actual PNG/JPEG/WebP decoding and malformed/dimension rejection; real isolated DB owner/client/revocation, immutable receipts/quota/concurrent replay/GC roots; six-photo ordered canonical projection and fail-closed stored-manifest mismatch; website upload/reorder/explicit-choice/reload same-key body behavior. This is local qualification, not live JWT/customer/provider/hosting acceptance.

Implementation review found that prose such as "use all provided photos" / "use exactly N" is not recognized by the existing phrase parser, and its count was only a minimum. The structured web choice is therefore retained in the immutable Studio run request and used for deterministic selection. An explicit count carries a maximum equal to its minimum in solver, persisted selection, prompt and hard QA. Website Source photos are always content; model classification can describe them but cannot silently discard them as a logo/reference. Automatic mode still honors the user's textual instructions and allows one or several photos. No global style is imposed.
