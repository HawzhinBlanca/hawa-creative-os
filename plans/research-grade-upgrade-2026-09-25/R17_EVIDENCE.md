# R17 — Approval of explicitly selected export bytes

**Date:** 2026-09-25. **Status:** in progress. The exact-revision capture and post-edit invalidation exit criteria are not met.

The approval route formerly accepted an approved decision with no selected export, and silently used available exports when the caller omitted `pinnedExportIds`. That let an approval move a task to `APPROVED` with nothing to deliver and left the reviewer’s choice ambiguous. It now requires at least one explicit export ID. Before writing the approval, Core resolves each selected ID for the task and reads its stored bytes; a missing file, changed size or changed SHA-256 is refused. The mandatory QA check is evaluated first so missing or failed QA remains a 412 refusal. The Desk Work screen already supplied explicit selected IDs and disabled approval with an empty selection.

Negative controls cover zero selected exports despite an available file, no publish after refusal, and a metadata/byte mismatch. Existing lifecycle, delivery, Canva capture and office-pilot fixtures were updated to select an export explicitly; the 100-task pilot test uses in-memory synthetic export bytes and **does not constitute a production pilot**. A fixed-tree full suite passed **406 files / 3,032 tests**, with 4 files / 48 tests skipped. `pnpm typecheck` passed, including test suites. No production flag, model or deployment was changed.

**Second pass:** A checked PPTX capture retrieved after an approved revision now creates a new revision and QC run. The revision repository appends `approval.invalidated` and resets the task to human review. A mocked-Canva, isolated-PostgreSQL integration test approved one capture, retrieved a second, observed a new revision and invalidation event, and verified that the Desk publish route refused the task. The focused file passed 4 tests. The first whole-suite run then failed two unrelated Kurdish-intake assertions (`headlineCkb` was undefined rather than empty); that file passed all 7 tests alone, and an unchanged full-suite rerun passed **406 files / 3,033 tests**, with 4 files / 48 tests skipped. The intermittent first run remains a test reliability issue, not silently counted as green. Typecheck passed after this change.

**Third pass:** Both Core delivery and the Delivery workflow now refuse an approval if PostgreSQL holds any Canva export newer than that approval. A database integration test simulated the gap after export bytes were stored but before the QC callback ran; ordinary delivery and the explicit stored-approval policy both refused before a publisher was called. This covers PNG/PDF/PPTX recapture at the delivery lookup, even where the route could not record a new revision. The focused classifier/intake/delivery tests passed 56 tests. A fixed-tree full suite passed **406 files / 3,035 tests**, with 4 files / 48 tests skipped; TypeScript checks passed. The two intermittent Kurdish-intake failures were traced to the test process inheriting a real `OPENAI_API_KEY`. The test environment now blanks OpenAI/Anthropic/Gemini keys by default; explicit empty copy sections with no prior design are classified deterministically as new requests, so an occasional model answer cannot erase their missing-copy state. A mock-provider negative test asserts zero provider calls for that case.

This establishes a nonempty, byte-verified pin at approval, invalidates a normal post-approval **checked PPTX** recapture, and refuses delivery after any newer stored Canva export. It does **not** prove that every selected file belongs to the exact reviewed revision. The current Canva export table has task, design and binding-version association but no revision ID; the separate capture-set row is not a required approval input. Edits without a capture, a race between freshness lookup and publication effects, and deployment recovery are not yet covered. The route still logs and contains QC-recording errors after retrieval; the delivery guard prevents sending while a newer export is stored, but the task may continue to appear approved until reconciliation. R17 remains open until exact revision/capture/QC linkage and all post-edit invalidation paths are exercised in integration and deployment drills. The prior FR-044 traceability language claiming full exact artifact binding is therefore broader than actual behavior; the contradiction is recorded in the wiki.

**Fourth pass — exact checked export and capture version:** The initial Canva bridge, delayed-check recorder and re-drive bridge now put the immutable export artifact ID and provider `designUpdatedAt` value in the QC report. The approval repository checks these in the task-locked transaction: the latest passing QC run must name the selected PPTX by ID and SHA-256, and every pinned file must match stored bytes, the bound Canva design and binding version, and that same provider design version. The delayed-check recorder also locks the task before recording QC, serializing a normal recapture with approval. Core exposes the checked artifact ID and capture version to the Desk, which preselects its PPTX with an image from the same version, blocks mixed-version selections, and explains why the deck is required. Preexisting Canva QC rows without an exact artifact ID fail closed through the production Canva export store; synthetic workflow fixtures using an in-memory store remain generic workflow tests.

Negative controls reproduced the original bug (an older export was accepted for a newly checked revision), then verified a 422 refusal for that older export and for a checked deck paired with an image from a different provider design version. Positive isolated-PostgreSQL tests cover the normal Canva-to-delivery chain, delayed QA recovery, re-drive, and Desk selection. The fixed-tree full suite on the final source passed **406 files / 3,038 tests**, with 4 files / 48 tests skipped; `pnpm typecheck` passed. The five focused capture and Desk files passed 16 tests after the task-lock and alternate re-drive bridge change; a further focused Core/Desk check confirmed that the task-state API returns the provider version and the Desk filters on it.

R17 stays **in progress**. The provider version groups exports but is only as precise as Canva's reported update value. The system has not proved detection of an edit with no new capture, a capture committed concurrently with publication effects, or recovery after a real deployment interruption. Approval records created before this evidence link also need an explicit migration or recapture policy before release.

**Fifth pass — request-owned approval proof:** Source `109fa63` and ADR-042 bind the signed first lifecycle approval to the latest QC run/report hash and selected stored bytes. Core verifies byte size and SHA-256 before signing; the task-locked repository rechecks the exact latest run, checked deck, capture version and binding before committing. A lost-answer retry uses the immutable stored proof. Negative controls refuse failed latest QA and a run ID that changed between inspection and projection. The focused chain passed 2 files/8 tests and the source suite passed 419 files/3,126 tests (4 files/48 tests skipped), with TypeScript, lint and blueprint 751/0/0 passing. The test's deck bytes and passing QC are synthetic, and the gateway hop is simulated. This does not close uncaptured Canva edits, a publication-time race, actual visual quality, or deployed restoration; R17 remains **in progress**.
