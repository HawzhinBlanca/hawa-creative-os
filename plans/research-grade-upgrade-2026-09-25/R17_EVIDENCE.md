# R17 — Approval of explicitly selected export bytes

**Date:** 2026-09-25. **Status:** in progress. The exact-revision capture and post-edit invalidation exit criteria are not met.

The approval route formerly accepted an approved decision with no selected export, and silently used available exports when the caller omitted `pinnedExportIds`. That let an approval move a task to `APPROVED` with nothing to deliver and left the reviewer’s choice ambiguous. It now requires at least one explicit export ID. Before writing the approval, Core resolves each selected ID for the task and reads its stored bytes; a missing file, changed size or changed SHA-256 is refused. The mandatory QA check is evaluated first so missing or failed QA remains a 412 refusal. The Desk Work screen already supplied explicit selected IDs and disabled approval with an empty selection.

Negative controls cover zero selected exports despite an available file, no publish after refusal, and a metadata/byte mismatch. Existing lifecycle, delivery, Canva capture and office-pilot fixtures were updated to select an export explicitly; the 100-task pilot test uses in-memory synthetic export bytes and **does not constitute a production pilot**. A fixed-tree full suite passed **406 files / 3,032 tests**, with 4 files / 48 tests skipped. `pnpm typecheck` passed, including test suites. No production flag, model or deployment was changed.

This establishes a nonempty, byte-verified pin at approval and prevents the empty-approved state. It does **not** prove that every selected file belongs to the exact reviewed revision. The current Canva export table has task, design and binding-version association but no revision ID; the separate capture-set row is not a required approval input. A later Canva edit or recapture is not yet guaranteed to invalidate a prior approval before publication. R17 remains open until exact revision/capture/QC linkage and that invalidation are exercised in integration and deployment drills. The prior FR-044 traceability language claiming full exact artifact binding is therefore narrower than actual behavior; the contradiction is recorded in the wiki.
