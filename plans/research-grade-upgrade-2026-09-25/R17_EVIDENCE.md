# R17 — Approval of explicitly selected export bytes

**Date:** 2026-09-25. **Status:** in progress. The exact-revision capture and post-edit invalidation exit criteria are not met.

The approval route formerly accepted an approved decision with no selected export, and silently used available exports when the caller omitted `pinnedExportIds`. That let an approval move a task to `APPROVED` with nothing to deliver and left the reviewer’s choice ambiguous. It now requires at least one explicit export ID. Before writing the approval, Core resolves each selected ID for the task and reads its stored bytes; a missing file, changed size or changed SHA-256 is refused. The mandatory QA check is evaluated first so missing or failed QA remains a 412 refusal. The Desk Work screen already supplied explicit selected IDs and disabled approval with an empty selection.

Negative controls cover zero selected exports despite an available file, no publish after refusal, and a metadata/byte mismatch. Existing lifecycle, delivery, Canva capture and office-pilot fixtures were updated to select an export explicitly; the 100-task pilot test uses in-memory synthetic export bytes and **does not constitute a production pilot**. A fixed-tree full suite passed **406 files / 3,032 tests**, with 4 files / 48 tests skipped. `pnpm typecheck` passed, including test suites. No production flag, model or deployment was changed.

**Second pass:** A checked PPTX capture retrieved after an approved revision now creates a new revision and QC run. The revision repository appends `approval.invalidated` and resets the task to human review. A mocked-Canva, isolated-PostgreSQL integration test approved one capture, retrieved a second, observed a new revision and invalidation event, and verified that the Desk publish route refused the task. The focused file passed 4 tests. The first whole-suite run then failed two unrelated Kurdish-intake assertions (`headlineCkb` was undefined rather than empty); that file passed all 7 tests alone, and an unchanged full-suite rerun passed **406 files / 3,033 tests**, with 4 files / 48 tests skipped. The intermittent first run remains a test reliability issue, not silently counted as green. Typecheck passed after this change.

This establishes a nonempty, byte-verified pin at approval and invalidates a normal post-approval **checked PPTX** recapture. It does **not** prove that every selected file belongs to the exact reviewed revision. The current Canva export table has task, design and binding-version association but no revision ID; the separate capture-set row is not a required approval input. PNG/PDF-only recapture, edits without a capture, a failure between persisting export bytes and recording QC, and concurrent recapture/publication are not yet covered by the invalidation proof. The route currently logs and contains QC-recording errors after retrieval; this can leave an earlier approval live. R17 remains open until exact revision/capture/QC linkage and all post-edit invalidation paths are exercised in integration and deployment drills. The prior FR-044 traceability language claiming full exact artifact binding is therefore broader than actual behavior; the contradiction is recorded in the wiki.
