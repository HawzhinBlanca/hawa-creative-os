# Explicit request deliverables and factual operating titles

Date: 2026-10-01. ADR186. Base:84e41f5b. Production observed:4e500451.

## Objective and scope

Repair the remaining S022/S031a intake defects without replacing the existing durable workflow. An explicitly requested deliverable owns one immutable request/task/client/canvas and its own factual source. Ordinary conversation, a photo count and literal copy authorize no additional task. Keep original source evidence and existing per-language identities. The whole-app goal, flexible content-aware design W1–W6, native Canva/font/logo/real-human qualification and production rollout remain separate unfinished work.

## Implementation and acceptance

- Pure bounded source policy supports explicit numeric counts, numbered or role sections, and several formats/subjects requested together. Eight is the combined deliverable/language bound; never silently trim. Unsupported requested canvases refuse explicitly. No model call or new dependency is used for this decision.
- Core application service creates stable child identities, binds positive client mentions before retrieval, separates each child's words and honors its source-derived format. Complete decisions and manual-allocation reasons are durable Core evidence outside worker drafts.
- Worker advertises its bound and validates all children, count, identities and source-event bindings. Historical/draining clients unable to carry a whole decision receive a refusal, never a reduced bundle. Existing language behavior and identities remain compatible.
- Ambiguous explicit counts retain separate manual tasks and durable office diagnostics, with no guessed factual copy or automatic paid dispatch. Clear S022 must produce both actual automatic requests/runs; this fallback cannot substitute for it.
- Daily admission locks the counted outbox boundary in its creation transaction and replays saved automatic/manual admission. Concurrency must admit no more than the remaining allowance.
- Original-brief holds cover every child, including plural natural language. Actual paid ledger records zero calls until a person resumes an individual child; other children stay held.
- Pending-project, reply, photo, album and edit paths retain all siblings or expose ambiguity. Shared-source edits atomically record a separately acknowledged note for each active child; no copy is changed. Reading one note cannot release another child's delivery hold.
- Titles select only the user's own event subject when copy starts with metadata. Shared instructions cannot become the title; submitted factual copy is preserved.
