# Local PDF text inspection (ADR-070)

Desk → Brand DNA → select client → **Inspect a PDF** → **Preview PDF text**.
Check every page against the original. This is a transient preview: the source
and extracted text are not saved, approved, indexed, or made into a design task.
A failed preview never becomes an empty successful result.

## Capability boundary

Pinned Docling 2.130.0 with docling-parse 7.22.0 reads native PDF text cells and
measured page boxes, without models, OCR or external requests. The response records
source SHA-256, extractor version, stable chunk IDs and top-left point coordinates.
The TypeScript caller independently validates the hash, version, page coverage,
coordinates and output bounds. Plain UTF-8 text retains original byte hashing and
character offsets, without invented pages or regions.

Limits: 20 MiB input, 40 pages, 10,000 text cells, one million text characters,
8 MiB response, one active job, five-second sidecar upload timeout, 28-second
worker deadline, 30-second parent deadline and 35-second client request deadline.
Core also bounds its upload to ten seconds. The container is non-root, read-only,
768 MiB memory, one CPU, 32 processes, with a 64 MiB temporary filesystem.

Native text order is unverified. Table structure and images are not extracted.
Every page must yield text; scanned/blank pages, partial conversions and malformed
PDFs are refused for manual review. A text-bearing scanned page can still omit
visual information. English synthetic fixtures do not establish Sorani/Arabic PDF
fidelity. Request-owned PDF/voice intake and approved document indexing remain open.

## Disposable acceptance proof

From the repository root, with Docker running and the existing chaos worker image
built (`packages/testkit/chaos/README.md`), run:

```sh
pnpm --filter @hawa/retrieval build
docker compose -p hawa-docling-proof -f services/docling/compose.yml up -d --build
docker run --rm --network hawa-docling-proof_parser --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user 65532:65532 --memory 256m --pids-limit 32 \
  --mount type=bind,src="$PWD/packages/retrieval/dist",dst=/workspace/packages/retrieval/dist,readonly \
  --mount type=bind,src="$PWD/services/docling",dst=/workspace/services/docling,readonly \
  --entrypoint node hawa-chaos-worker:local /workspace/services/docling/probe.mjs
docker compose -p hawa-docling-proof -f services/docling/compose.yml down
```

The probe checks compressed two-page text/boxes, original byte hashes, deterministic
replay, blank and over-page-limit refusal, malformed PDF refusal and an oversized
HTTP body. Fixtures are office-generated by `fixtures/generate.py`; no client data
is used. Tests of the route, parser boundaries and React preview run in normal
Vitest. The initial native dependency install was disposable; production packages
are fixed in `requirements.lock`, and the Python base image is digest-pinned.

## Enabling the service

Production is not enabled by this change. Qualify the image and record its digest
before using it. Attach **only Core and this parser** to a dedicated internal
Docker network, retaining Core's existing networks. Configure Core with
`HAWA_DOCLING_URL=http://docling:8091`. Keep the parser's resource/security settings
from `compose.yml`, without host ports, credentials, source mounts or an egress
network. The application never mounts the Docker socket or starts containers.

The parser has no public authentication layer: its only callers must be on that
private network. Core authenticates the user and checks PostgreSQL client access
before and after conversion. The URL is deployment configuration, never uploaded
content; the adapter accepts only loopback or the fixed `docling` service name and
rejects redirects. The API is `POST /v1/clients/{clientId}/documents/inspect` with
raw `application/pdf` bytes. Missing configuration or service yields a visible
503, and the original document remains with the user.

## Retained request sources (ADR-071)

Desk also offers **Save PDF for a request** through `POST /v1/clients/{clientId}/documents`.
Migration 041, PostgreSQL and `HAWA_BLOB_DIR` are required. Original bytes are retained
in the existing blob store; immutable client-scoped extraction receipts become GC
roots before task creation. Re-uploading the same source/version reuses its receipt.
Recent saved sources can be reopened, and original downloads verify their hashes.
Missing or corrupt storage refuses new request creation; it never substitutes text.

The operator explicitly enters/edits copy and confirms it against the original.
The existing manual Desk task transaction binds the receipt hashes, authenticated
actor and exact copy to one task/event/outbox with a stable request key. This neither
indexes the document nor approves knowledge or publication. A lost reply keeps the
frozen browser request for an unchanged retry. Browser storage is tied to that browser;
clearing it discards pending reconciliation identity, so check Work before creating
another request. Originals/receipts follow the current append-only audit retention;
there is no automatic expiry or source-purge UI in this slice.

Rollback: remove Core's parser URL and stop the sidecar to stop new extraction.
Retained evidence, source downloads and exact task retries remain available. Keep
migration 041 and the blob roots; never drop saved originals as a rollback step.
Production activation and a real office PDF quality review remain separate gates.
