# Hawdesign architecture and design pipeline reality check

**Date:** 2026-09-25 Baghdad  
**Checkout and live build:** `studio-v2` at `1c1316d`  
**Method:** current source, deployed read-only health/flag checks, the September 18 design artifacts, prior adversarial findings, and a fresh release-gate run. No production setting or user design was changed.

## Verdict

Hawdesign has substantial engineering discipline and a working Canva draft path. It is not evidenced as a universal 10/10 architecture, an end-to-end approved-delivery system, or an outstanding creative director. The software and visual-quality claims must be reported separately. A passing build cannot certify taste; a draft link cannot certify approval and archive delivery.

The live Core reported `DESIGN_PIPELINE_V3=off`, `DESIGN_STUDIO_V2=off`, `HAWA_TELEGRAM_POLLER=core`; pilot chats are configured for v3, while `HAWA_LIFECYCLE_CHATS` and `HAWA_WORKER_TOKEN` are empty. Its last 48-hour snapshot showed 7 briefs, 4 drafts, 0 approvals, 0 deliveries, and a paid model probe marked `unverified`, yet the aggregate status was `healthy`. These are facts about the reported window, not evidence that the other three briefs failed or that users wanted the full archive flow. The funnel explicitly treats editable Canva draft handoff as the current product boundary (`apps/core/src/services/funnel-monitor.ts:101`).

The fresh release gate passed stages 1–6 (typecheck, schema, security scan, pack, manifest, isolated database guard) and **failed stage 7**: 395 test files passed, 4 failed; 2,991 tests passed, 9 failed. The same four files failed in a targeted rerun. Several failing tests expect passive Telegram text to create a task, and one expects legacy response fields; the immediate user impact is not established. The gate is red and must be reconciled before another release claim. Evidence: `output/repairs/2026-09-19-architecture-remediation/FULL_TEST_SUITE_RUN.log` and the targeted replay on 2026-09-25.

## What is strong

- The current source has scoped database state, per-file test databases, an enforceable release manifest, narrower Core modules, improved worker deploy handling, and failure-injection tests. The September 24 programme documents the baseline and each slice (`output/plans/2026-09-24-architecture-programme/PLAN.md`, `WAVE5_EVIDENCE.md`, `WAVE6_EVIDENCE.md`).
- Canva import gives an editable working design; the worker checks exported PPTX text and fonts before declaring a draft ready (`apps/worker/src/canva-draft-workflow.ts:510`).
- GPT-6 Astra and GPT Image 2.5 Sunburst are currently top-tier models in their respective official catalogs. Model age is not the principal weakness here. [OpenAI model catalog](https://developers.openai.com/api/docs/models), [Sunburst model](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst).
- The resvg switch was rejected by measured parity failures; keeping the qualified rsvg renderer was sound (`output/plans/2026-09-24-architecture-programme/WAVE2_EVIDENCE.md`).

## Recommended order

1. Reconcile the nine release-gate failures and stop publishing a single 10/10 score. Keep the current blue/green, database-isolation and renderer safeguards.
2. Finish and canary the approved September 24 lifecycle programme, with live receipt and restore evidence. Do not flip all chats at once.
3. Build the cross-client BrandKit/DesignIntent, real example retrieval, and sealed human design benchmark before spending on a new model or a second framework.
4. Make the actual Canva export the hard admission artifact, and close the editability/recovery claim with an executed restore drill.
5. Move paid model calls behind one policy and durable result boundary; only then compare Astra effort/model alternatives on quality per dollar and latency.

**Evidence limit:** This audit did not send a new paid design request or modify live production. Historical September 18 images show defects of that build; the present source has since changed. Current artistic rank requires a new blinded human assessment of current exports.
