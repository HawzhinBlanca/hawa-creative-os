Hawa Architecture Programme

Eight improvements, planned as phased, measurable work. Each change has a measured need, a proof before it ships, and a way back. The plan comes from the two review rounds of 24 September (about 95 bugs, each reproduced by a failing test) and four research reports written for it: a codebase inventory, Restate, resvg against rsvg, and the supporting technology.

Calendar: 8–10 weeks Effort: about 67 engineer-days ADRs: 034–037, proposed Repo copy: output/plans/2026-09-24-architecture-programme/PLAN.md

Real requests are not blocked. Phase 0 should land within the first week of real use, before the office as a whole is invited.

Why: where the bugs came from

About 95 bugs in one day of review fall into four structural weak spots.

Weak spotEvidence

Core holds 24 stateful maps and sets; several are read before Postgres.A delivery stuck after a restart; Canva imports and studio runs nobody abandoned; outcomes lost when Core was down; approval buttons dead after a restart; nine call sites read a stale cached status that feeds delivery, publish and decisions. Pictures as base64 inside rows.A reference photo is written three times in Postgres plus Restate; a rotated 12 MP photo broke every render (rsvg's 10 MB attribute limit); reply lookups scan JSON carrying images; in the test database 265 of 334 MB is PPTX sources inside one table.

Research added three risks the plan handles first:

  1. Deploys replay running work on new code. The worker is re-registered at the same address on every deploy, with a forced fallback. Restate pins work to a deployment; swapping the container behind it replays in-flight work on changed code, the documented cause of journal mismatches. Today's deploys were safe only because nothing was in flight.
  2. Network calls inside open transactions. A Telegram document upload can take 60 s inside a transaction the database kills after 30 s idle: the delivery can be sent twice.
  3. Desk load grows with tasks and tabs. The Desk reads every page of the task list every 30 s and a second after every task event; each row runs six subqueries, two unindexed; the readiness check Docker polls every 10 s is the full health handler.

Principles

  1. Measured need, measured result. A baseline and a target number before work starts.
  2. Strangler, not rewrite. One slice at a time, behind a per-chat flag, with the old path kept until the new one has run in production.
  3. Tests before moves. Behavioural and contract tests replace text-matching tests before code moves.
  4. No handler waits for a person. Waiting is state; each event is a short handler.
  1. Every side effect has a deterministic key (requestId:revision:step), and every boundary reconciles before acting.
  2. One owner per fact. Postgres for what the Desk reads, Restate for where a request is, the file store for bytes. Nothing in Core's memory holds truth.
  3. An ADR before a foundation changes; the lead re-runs every proof an agent reports.

Target architecture

  • Restate decides transitions. Postgres is the projection the Desk reads, written by Core with expected revisions. Core is the API and the domain services, with no lifecycle state of its own.
  • Reminders are delayed self-sends ("next office morning") and run on whatever code is current when they fire.
  • The worker runs as two colours, each registered at its own address; a deploy goes to the drained colour.

Phase 1 · Foundations for change

weeks 2–4 · about 21 days, parallel streams

1.1 Tests on their own databases 3 d

A global setup builds a template database keyed by a hash of the schema, security policies, migrations, seed and fixtures, under a lock (worktrees share the server). Each test file clones its own database and drops it afterwards; the connection guard accepts only those names. The test server runs non-durable on a RAM disk. Then files run in parallel.

Pass: suite ≤ 2 min (about 4.5 now); 20 green runs in a row; no test lifts the daily cap to pass.

Why not a rolled-back transaction per test: the app opens its own transactions, row-level security depends on transaction-local settings, and commit-time behaviour would never run.

1.2 One status vocabulary 3 d

packages/contracts owns the database states, API statuses, legal transitions and Desk labels. An unknown word is an error, never received; one event shape {taskId, from, to, version, at}; the API description and JSON schema are generated from it; the Desk refuses to approve an unknown status.

Pass: one list of statuses in the repository; a contract test fails when any layer adds a word.

1.3 Split app.ts 8 d, one group per pull request

Text-matching tests become behavioural first. Then, in this order: dead code (eight shadowed routes, unused helpers, fixtures) → leaves → clients → revisions and decisions → the Canva outcome handler, behind a contract test → publish and delivery → controls, replacing the catch-all route → tasks and Desk → WhatsApp → Telegram intake last. Each group removes the in-memory maps it owns.

Pass: app.ts ≤ 1,500 lines; no module over 800; no truth-holding map left in Core; every step green and deployed.

1.4 Observability 3 d

Structured logs (pino) in Core and the worker with one request context {requestId, taskId, chatId, tenantId}, set at every HTTP request, Restate handler and Telegram update, and passed between services. Tokens are stripped from URLs. One Vector container writes daily log files under ~/.hawa/logs for 30 days, so logs survive container replacement. Office numbers come from tables: cost per design, time to first draft, rounds per design, paused work. OpenTelemetry waits; a Jaeger profile can be started on demand.

Pass: one command shows every log line of one request across Core, worker and nginx, including from containers a deploy replaced.

1.5 Desk server state 4 d · ADR-037

TanStack Query: numbered pages with a server total; server-side filter and search (treating ي/ی and ك/ک alike); events invalidate the list and the task, coalesced over 300 ms, and everything after a reconnect; polling only while the stream is down; one path for an expired session; approvals show "Approving…" and never change the cached status before the server confirms. The session token leaves the stream URL for a short-lived ticket.

Pass: a new draft appears within 2 s of its event; an idle tab makes no list requests while connected; an expired session reaches sign-in from any screen.

Phase 2 · Restate owns the request lifecycle

Phase 3 · Pictures and rendering

weeks 6–9 · about 15 days

3.1 Content-addressed file store 6 d · ADR-035

Files under ~/.hawa/blobs/sha256/ab/<hash>, written atomically, read-only once written; a blobs table with foreign keys from every referencing row; mark-and-sweep clean-up with a 14-day grace period; Core checks access on the referencing row, then nginx serves the file. Backups take the database first, then the files. Moves, in order: reference photos (written once, as a reference), plan sources (the bulk), candidate previews, cut-outs, comparison images. Canva export bytes stay in the database for now. The renderer reads pictures as files beside the SVG, never inlined.

Pass: a request's payload ≤ 4 KB; no inlined picture over 100 KB in any SVG; database size and dump time measured before and after; the restore drill includes the files.

3.2 Outlines and glows as pictures 3 d · ADR-036

Drawn by a distance transform in our code and embedded in both the preview and the Canva bake, replacing the SVG filter behind the 23 s outline.

Pass: within 1 device pixel of today's outlines; a 24 px outline at 2x in under 1 s.

3.3 The resvg gate 3 d spike + 3 d if GO · ADR-036

In the production image, render 200 stored layouts in every style, plus built sets of photos, cut-outs and Kurdish text, with rsvg (today's and the new markup) and with the resvg 0.48 command-line tool.

GO only if: no crash, blank or warning; every text line within 1 px (Latin) or 2 px (Arabic), with no word-order change; every treatment within tolerance; median SSIM ≥ 0.99 and minimum ≥ 0.97; identical bytes across repeats and between Mac and container; no slower at p95 and nothing over 5 s; memory ≤ 1.5x; a person signs off the lowest-scoring pairs and the Kurdish sheet.

On GO, only the rasteriser changes, to the resvg command-line tool run as a separate process (keeping the timeout and memory isolation), built from source in the image; rsvg stays one release; the preview and the bake always use the same renderer. Not the in-process Node package: it bundles a 2023 engine (no WebP, blank CMYK photos, crashes on some Arabic text).

  2. Restate decides a request's stage; Postgres is the projection (ADR-034).
  3. The file store as a folder under ~/.hawa/blobs, visible to the Mac's backups (ADR-035).
  4. Add TanStack Query to the Desk (ADR-037; the measured need is in it).

  6. Replace the Google Drive placeholder key.
  7. Accept a Rust build stage in the core image if the resvg gate passes (ADR-036).

Not doing, and why

  • Kubernetes, microservices, a second host: one Mac, one office; this week's failures were state and structure, not scale.
  • An agent framework: ruled out by AGENTS.md; the pipeline is fixed stages.
  • A vector database, a new runtime, GraphQL: no measured need.
  • A permanent observability stack: heavy on a laptop that has already run out of swap; logs with a request id carry the correlation.
  • An S3 server: MinIO's community edition is archived; Garage only if the S3 API is ever needed.
  • The in-process resvg Node package: a stale engine; see 3.3.
