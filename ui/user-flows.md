# Hawa Desk User Flows

## Flow 1 — Telegram request to final files

1. Requester mentions bot or opens Mini App.
2. Verified message appears in Inbox.
3. Explicit promotion creates task.
4. Deterministic mapping resolves client/project or asks manager.
5. Brief shows exact copy and missing facts.
6. Manager supplies/approves facts.
7. System produces editable draft and QA evidence.
8. Reviewer opens full canvas, edits or requests scoped revision.
9. Approval binds exact revision.
10. Drive/source package and Sheet row are verified.
11. Final link returns to Telegram thread.

## Flow 2 — Direct office task

1. User opens New Task in Hawa Desk.
2. Selects client/project and attaches source.
3. Enters exact copy, dimensions, deadline.
4. System skips routing ambiguity and proceeds through normal brief/design/review.

## Flow 3 — Ambiguous client

1. Message matches two allowed clients.
2. Task stops in Routing Review before retrieval.
3. UI shows evidence/candidates and “Why blocked.”
4. Manager selects client/project.
5. Selection becomes routing evidence; no cross-client context was fetched.

## Flow 4 — Manual design edit

1. Reviewer opens editable studio at revision N.
2. Edits one or more nodes.
3. Save creates N+1 and semantic diff.
4. Critical QA reruns.
5. Prior approval is invalidated.
6. N+1 returns to review.

## Flow 5 — Failed model/provider

1. Task shows failed step and preserved completed work.
2. Operator sees exact model, attempts, policy, cost, and admitted fallback.
3. Operator pauses, waits, switches fallback, or routes to human.
4. Restate resumes from checkpoint; publication/source identity is unchanged.

## Flow 6 — Rule proposal

1. Repeated corrections produce candidate rule.
2. Client DNA manager reviews evidence/counterexamples/scope.
3. Manager activates/narrows/rejects.
4. Activation creates new DNA version and evaluation cases.
5. Future context packs use the new version.
